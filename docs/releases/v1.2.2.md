# v1.2.2 — préparation du correctif du menu mobile

Base : `main` / v1.2.1, commit
`88a4c82d7197caf99ae903469c842adabae7bf42`.
Branche : `codex/fix-mobile-menu-scroll`. Version du paquet, version racine

## Correctif

Les dix destinations restent accessibles sur écran de faible hauteur : seule
la liste défile, le bouton Fermer conserve sa hauteur et reste visible. Le menu
respecte les safe areas et bloque le défilement de la page pendant son ouverture.
Le popover HTML `auto`, Échap, les commandes natives et les animations existantes
sont conservés. Les liens mobiles sont explicitement inclus dans la tabulation.
La page 404 versionnée est régénérée depuis les composants et styles réels.

La [recette et les captures avant/après](../mobile-menu-validation.md) détaillent
les formats 320×568, 390×844, 568×320 et 844×390, la rotation, le clavier, le focus,
les dix routes, le zoom natif à 200 %, le tactile et les safe areas simulées.
Le desktop est contrôlé à 950, 1280 et 1440 px ; la comparaison 1440×900 avec
la base ne présente aucun pixel différent.

## Dépendances

Le passage de 1.2.1 à 1.2.2 modifie uniquement les trois métadonnées de version.
Les déclarations de dépendances et toutes les entrées des paquets verrouillés
restent identiques à celles du correctif déjà préparé, vérification automatique
à l'appui. Aucune mise à jour, résolution npm, correction d'audit ou migration
n'est effectuée pendant cette finalisation.

Par rapport à `main`, le correctif préparé ajoute uniquement Playwright 1.64.1
comme outil de test de développement (`@playwright/test`, `playwright`,
`playwright-core`). Les dépendances de production et les outils existants
conservent leurs versions.

## Validation et limites

Recette locale : **58 tests Angular**, **5 tests HTML**, typecheck et build de
production réussis ; **33 tests navigateur réussis**, 3 exclusions WebKit.
Les deux animations d'entrée sont contrôlées à 0,5 s, puis désactivées avec
`prefers-reduced-motion: reduce`.

La CI Ubuntu 24.04 contrôle les types, Angular/Chrome Headless, le build complet,
les documents HTML, les règles HTTP/HTTPS sous Apache, l'audit de production
et le seuil élevé/critique de l'outillage. Le job `mobile-menu` exécute aussi
Chrome et WebKit et archive le rapport avec ses captures pendant 14 jours.
Edge est testé localement. Les statuts et journaux GitHub Actions sur le dernier
commit de la PR font foi pour les résultats Ubuntu.

WebKit exécute les scénarios de dimensions, clavier/focus, défilement à la molette,
fermeture, navigation, rotation, animations et desktop. Seuls trois tests sont
exclus : zoom natif configuré dans un profil Chrome/Edge, surcharge des safe areas
par CDP, et injection de balayages tactiles par CDP. Ce sont des limites
d'instrumentation, pas des validations implicites de ces fonctions sur Safari.
La recette automatisée ne remplace pas un essai sur appareil iOS physique avec
encoche et barres Safari, ni un audit complet avec lecteur d'écran.

Cette étape crée les commits et la PR uniquement. Aucune fusion, modification
Hostinger, livraison, création de tag ou Release n'est effectuée.
